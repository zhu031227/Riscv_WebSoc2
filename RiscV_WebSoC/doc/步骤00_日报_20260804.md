#### 进展和结果
- 按 7 步计划，从零编写 `tcp.c`，实现了前 4 步：
  - **步骤1（发送发动机）**：`tcp_checksum_build()` / `send_tcp_segment()` / `send_syn_ack()` / `send_ack()`
  - **步骤2（接收解析器）**：`tcp_parse_header()` 从 RX FIFO 按偏移读出源/目的端口、序列号、确认号、标志位
  - **步骤3（连接表）**：静态变量管理单个连接的状态、序列号、IP 和端口
  - **步骤4（三次握手状态机）**：`tcp_handler()` 实现 CLOSED → SYN_RECEIVED → ESTABLISHED 状态转移
- 对接 `main.c`：启动调 `tcp_init()`，收包流程中 `TCP_PROC` 分支调 `tcp_handler()`
- 编译通过（固件 3594 字节），待烧录验证

#### 遇到的问题
1. **`send_syn_ack` / `send_ack` 前置声明缺失**：函数定义在 `tcp_handler()` 之后，编译报 implicit declaration
2. **`eth.h` 声明不一致**：被改成了缓冲区版本的接口声明，与当前 `eth_proc()` 不匹配，编译报错
3. **`tcp.h` 未更新**：只有旧的 `tcp_test_send_syn_ack()` 声明，缺少 `tcp_init()` / `tcp_handler()`

#### 解决方法/经验总结
- C 文件中静态函数调用的前置声明必须放在调用者之前
- 头文件声明必须与实际实现保持同步

## 任务一：FPGA RISC-V Ping 固件调试与验证

### 进展和结果
- 手写 C 代码（ARP + IP + ICMP + 以太网驱动）经过多轮调试后，成功编译并烧录
- **Ping 169.254.1.1 通过**，ARP 请求/应答、ICMP 请求/应答均正常
- LED 流水灯正常运行，确认固件在跑

### 遇到的问题
1. **编译错误**：`ip.c` 调用 `icmp_process(frame, len)` 只传 2 参，函数定义要 3 参；缺少 `ETH_MAX_FRAME_LEN` / `lcpu_local_time_l` 定义
2. **Ping 不通**：FPGA 以太网完全静默，tcpdump 显示 PC 发了 ARP 请求但 FPGA 无应答

### 解决方法/经验总结
1. **编译问题**：补上 `ip_total_len` 提取和 `icmp_len` 计算，`ETH_MAX_FRAME_LEN` 移到 `eth.h`，`lcpu_local_time_l` 用 `rdcycle` 替代软件计数器
2. **Ping 不通（关键踩坑）**：通过分析和对比发现，LCPU 的 RX FIFO 访问有严格规则：
   - **永远不关 REN**（读使能保持为 1）
   - **每帧 POP 两次**（头部弹出包数据，尾部弹出推进到下一包）
   - **直接从 RX/TX FIFO 读写**，不能拷贝到内存缓冲区再处理
   - 初版代码用缓冲区 + `LCPU_RD_STOP()` 关 REN，导致 FIFO 卡死
3. 最终方案：采用 FIFO 直接读写模式，重写 `main.c` + 精简 `comlib.c`，复用已验证的 `eth.c`/`arp.c`/`ip.c`/`icmp.c`

## 任务二：TCP 协议栈第 1 步 — 发送发动机

### 进展和结果
- 按 7 步计划，先写"发送发动机"——不依赖接收逻辑，可独立调试验证
- 实现了 TCP 发送核心函数：
  - `fill_tcp_header()` — 填充 20 字节 TCP 头（端口/序列号/确认号/标志/窗口，全大端）
  - `tcp_checksum_build()` — 伪首部 + TCP 头 + 载荷 → 校验和（严格按 RFC 793）
  - `send_tcp_segment()` — 写 TCP 段到 TX FIFO → `LCPU_WR_PUSH_PACKET`
- 基于发送原语封装了 `send_syn_ack()` / `send_ack()` / `send_rst()`

### 遇到的问题
- **独立测试发不出包**：起初试图在 `main()` 启动时独立发送 SYN+ACK，自己构造完整以太网帧（MAC + IP + TCP），但 Wireshark 抓不到任何包
- 原因分析：`ip_header_update()` 在写 IP 头时会从 RX FIFO 拷贝部分字段（TOS、ID、TTL 等），而独立发送时 RX FIFO 为空，导致写入的是随机值；同时 MAC 头也未正确写入

### 解决方法/经验总结
- TCP 发送不能脱离收包流程独立运行：MAC 头由 `eth_proc()` 在处理收包时写入，IP 头由 `ip_header_update()` 写入，TCP 层只写 TCP 段
- 步骤 1 的代码逻辑正确，但验证需要等步骤 2（接收解析）打通后才能进行
