## 任务一：FPGA RISC-V Ping 固件调试与验证

### 进展和结果
- 手写 C 代码（ARP + IP + ICMP + 以太网驱动）经过多轮调试后，成功编译并烧录
- **Ping 169.254.1.1 通过**，ARP 请求/应答、ICMP 请求/应答均正常
- LED 流水灯正常运行，确认固件在跑

### 遇到的问题
1. **编译错误**：`ip.c` 调用 `icmp_process(frame, len)` 只传 2 参，函数定义要 3 参；缺少 `ETH_MAX_FRAME_LEN` / `lcpu_local_time_l` 定义
2. **Ping 不通**：FPGA 以太网完全静默，tcpdump 显示 PC 发了 ARP 请求但 FPGA 无应答

### 解决方法/经验总结
1. **编译问题**：补上 `ip_total_len` 提取和 `icmp_len` 计算，`ETH_MAX_FRAME_LEN` 移到 `eth.h`，`lcpu_local_time_l` 用 `rdcycle` 替代软件计数器
2. **Ping 不通（关键踩坑）**：对比原项目工作代码后发现，LCPU 的 RX FIFO 访问有严格规则：
   - **永远不关 REN**（读使能保持为 1）
   - **每帧 POP 两次**（头部弹出包数据，尾部弹出推进到下一包）
   - **直接从 RX/TX FIFO 读写**，不能拷贝到内存缓冲区再处理
   - 初版代码用缓冲区 + `LCPU_RD_STOP()` 关 REN，导致 FIFO 卡死
3. 最终方案：复制原项目 `lcpu_general.h` + `eth.c`/`arp.c`/`ip.c`/`icmp.c`，重写 `main.c` + 最小 `comlib.c`

## 任务二：TCP 协议栈第 1 步 — 发送发动机

### 进展和结果
- 对照原项目 `tcp.c` 实现了 TCP 发送原语：
  - `fill_tcp_header()` — 填充 20 字节 TCP 头（端口/序列号/确认号/标志/窗口）
  - `tcp_checksum_build()` — 伪首部 + TCP 头 + 载荷 → 校验和（RFC 793）
  - `send_tcp_segment()` — 写 TCP 段到 TX FIFO → `LCPU_WR_PUSH_PACKET`
- 基于发送原语封装了 `send_syn_ack()` / `send_ack()` / `send_rst()`
- 函数签名与原项目一致，后续步骤可直接复用

### 遇到的问题
- **独立测试发不出包**：起初试图在 `main()` 启动时独立调用 `send_syn_ack()`，自己写 MAC+IP+TCP 全帧，但包未出现在 Wireshark
- 原因分析：原项目 TCP 发送依赖收包上下文——MAC 头由 `eth_proc()` 在处理收包时写入 TX FIFO，IP 头由 `ip_header_update()` 写入（同时从 RX FIFO 拷贝部分字段），TCP 层只写 TCP 段。独立构造全帧跳过了这个流程

### 解决方法/经验总结
- **TCP 发送必须挂在收包流程后面**：`eth_proc()` → `ip_proc()` → TCP 处理 → `send_syn_ack()`，不能独立调用
- 需先完成步骤 2（接收解析）才能验证步骤 1
