# 以太网物理层接口选型指南

## 1. 常见接口一览

### 1.1 MAC 与 PHY 之间的接口（芯片间互连）

| 接口 | 全称 | 引脚数 | 数据位宽 | 采样方式 | 时钟频率 @100M | 时钟频率 @1G | 时钟频率 @10G | 最大速率 |
|------|------|:------:|:--------:|:--------:|:-------------:|:-----------:|:------------:|:--------:|
| **MII** | Media Independent Interface | 18 | 4-bit | SDR | 25 MHz | — | — | 100 Mbps |
| **RMII** | Reduced MII | 8 | 2-bit | SDR | 50 MHz | — | — | 100 Mbps |
| **SMII** | Serial MII | 4 | 1-bit | SDR | 125 MHz | — | — | 100 Mbps |
| **GMII** | Gigabit MII | 24 | 8-bit | SDR | — | 125 MHz | — | 1 Gbps |
| **RGMII** | Reduced GMII | 12 | 4-bit | **DDR** | — | 125 MHz | — | 1 Gbps |
| **SGMII** | Serial GMII | 4 | 串行差分对 | SerDes | — | 1.25 GHz | — | 1 Gbps |
| **QSGMII** | Quad SGMII | 4 | 串行差分对 | SerDes | — | 5 GHz | — | 4×1 Gbps |
| **XGMII** | 10-Gigabit MII | 74 | 32-bit | **DDR** | — | — | 156.25 MHz | 10 Gbps |
| **USXGMII** | Universal SXGMII | 4 | 串行差分对 | SerDes | 1.25 GHz | 10.3125 GHz | 10.3125 GHz | 1G~10G |

### 1.2 接口命名规律

```
命名规则: [速率前缀] [R=Reduced/S=Serial/无] + MII

MII     — 基础百兆，18 根线
 ├── RMII   — Reduced: 砍到 8 根线 (100M)
 ├── SMII   — Serial: 串成 4 根线 (100M)
 │
 ├── GMII   — Giga: 千兆升级版，24 根线
 │    ├── RGMII  — Reduced: 砍到 12 根线 (1G)
 │    └── SGMII  — Serial: 串成差分对 (1G)
 │
 └── XGMII  — 10-Gigabit: 万兆版，74 根线
      └── USXGMII — Universal Serial: 串成差分对 (1G~10G)
```

> **CGMII** 不是 IEEE 标准接口。你可能在资料中看到的可能是笔误（CGMI = Converged GMI 或 Clock-Gated MII），市面上没有叫 CGMII 的 MAC-PHY 接口标准。

### 1.3 PHY 与线缆之间的接口（介质侧）

| 接口标准 | 介质 | 连接器 | 距离 | 速率 |
|---------|------|--------|------|------|
| 100BASE-TX | 双绞线 Cat5 | RJ45 | 100m | 100 Mbps |
| 1000BASE-T | 双绞线 Cat5e+ | RJ45 | 100m | 1 Gbps |
| 2.5GBASE-T | 双绞线 Cat5e+ | RJ45 | 100m | 2.5 Gbps |
| 5GBASE-T | 双绞线 Cat6 | RJ45 | 100m | 5 Gbps |
| 10GBASE-T | 双绞线 Cat6a+ | RJ45 | 30~100m | 10 Gbps |
| 1000BASE-X | 光纤多模 | SFP (LC) | 550m | 1 Gbps |
| 10GBASE-R | 光纤多模 | SFP+ (LC) | 300m | 10 Gbps |
| 25GBASE-R | 光纤单模 | SFP28 (LC) | 10km | 25 Gbps |

## 2. 评判标准

### 2.1 技术维度

| 标准 | 含义 | 为什么重要 |
|------|------|-----------|
| **数据速率** | 最高支持多大带宽 | 100M够不够？1G够不够？10G需不需要？ |
| **引脚数** | MAC-PHY之间需要几根信号线 | FPGA 引脚有限，尤其 QFP 封装引脚紧张。12 根 vs 24 根差距很大 |
| **采样方式** | SDR(单沿) / DDR(双沿) / SerDes(高速串行) | DDR 比 SDR 复杂，需要 IDDR/ODDR 原语；SerDes 最复杂，需要 GTP/GTX 硬核 |
| **时钟频率** | 线路上时钟跑多快 | 频率越高，PCB 走线越难，时序越难收敛 |
| **PCB 布线难度** | 画板的复杂度 | 12 根单端线需等长；4 根差分线简单但阻抗要求高 |
| **时序收敛难度** | FPGA 内能不能轻松跑过 timing | 125MHz DDR > 125MHz SDR > 25MHz SDR |
| **硬核需求** | 是否需要 SerDes (GTP/GTX/MGT) | 小 FPGA 可能没有 GTP；有 GTP 也不想为一个网口占用 |

### 2.2 工程维度

| 标准 | 含义 | 为什么重要 |
|------|------|-----------|
| **PHY 芯片可获得性** | 能不能买到、价格、交期 | 缺货时项目停摆 |
| **开发板支持** | 常见开发板是否自带这个 PHY | 省去画板、焊接、调试环节 |
| **参考设计** | 有没有现成成熟例程 | 从零写的风险和周期大很多 |
| **调试工具门槛** | 能不能用普通工具排查 | SGMII 的 1.25GHz 差分对普通示波器看不到；RGMII 的 125MHz 逻辑分析仪就能抓 |
| **功耗** | PHY + FPGA 接口功耗 | 并行口(SDR/DDR)功耗低，SerDes 收发器功耗高 |

### 2.3 项目适配维度

| 标准 | 含义 |
|------|------|
| **开发板自带什么** | 这是第一决定因素——板上焊好的 PHY 是什么接口，你就用什么 |
| **你实际需要的带宽** | 做 WebServer/UDP Echo 1G够；做视频流可能 10G |
| **FPGA 资源情况** | 剩余引脚数？有没有空闲 GTP/GTX？ |
| **你的技术能力** | 能调 SerDes 吗？懂时序收敛吗？ |
| **开发周期** | RGMII 三天上手，SGMII 可能要两周，USXGMII 可能一个月 |

## 4. 你的项目为什么用 RGMII

### 4.1 决定性因素：开发板自带的 PHY

```
ALINX ACX750 开发板
  └── 板载芯片: RTL8211 (千兆 PHY)
        └── MAC 侧接口: RGMII (12 根信号线)
        └── 线缆侧接口: RJ45 (1000BASE-T)
```

PCB 已经画死。FPGA 的 12 个特定引脚走线到 RTL8211 的 RGMII 口。**不是选了 RGMII，是开发板只有 RGMII。** 你没得选 GMII（引脚不够 24 个），也没得选 SGMII（板上没有 SerDes PHY）。

### 4.2 为什么 RGMII 比 GMII 更合理（即使引脚够用）

| | GMII | RGMII | 优劣 |
|---|:--:|:--:|---|
| 引脚数 | 24 | **12** | RGMII 少 12 根 = FPGA 多出 12 个 IO 给其他外设 |
| 采样方式 | SDR | DDR | GMII 更简单，RGMII 需要 IDDR/ODDR |
| 设计复杂度 | 低 | 中 | 这是 RGMII 的**代价**——省 12 根线换来 DDR 时序和 ODDR/IDDR 的额外工作 |
| 时钟 | 独立 TXC/RXC | 独立 TXC/RXC | 相同 |
| 业界地位 | 已被淘汰 | **当前主流** | 99% 千兆 PHY 都做 RGMII |
| 信号质量要求 | 一般 | 更高 | DDR 需要更严格的 PCB 等长走线和时序约束 |

**核心取舍**：
- RGMII 省了 12 根引脚（省资源），代价是时序更复杂（DDR、建立保持时间紧张）
- GMII 引脚多但简单，适合内部仿真和调试

### 4.3 为什么不用 SGMII（即使引脚更少）

| | RGMII | SGMII |
|---|:--:|:--:|
| 引脚 | 12 根单端 | **4 根 (2对差分)** |
| 需要 SerDes | ❌ | ✅ (需要 GTP 硬核) |
| XC7A35T 有 GTP | — | 有 4 个，但占用一个就少一个 |
| 调试 | ILA/逻辑分析仪直接看 | 必须有 ≥2.5GHz 带宽示波器 |
| PHY 配置 | 几乎免配 | 需要配置 GTP IP 参数 |
| 上手周期 | 3 天 | 2 周 |
| 开发板支持 | ✅ ACX750 自带 | ❌ ACX750 没有 SGMII PHY |

## 5. 选型决策流程

```
1. 开发板上有什么 PHY？
   ├─ 有 → 直接用板上的接口，别折腾
   └─ 没有（你要自己画板子）
           ↓
2. 需要多大带宽？
   ├─ 100M  → 引脚紧张选 RMII (8根)，简单选 MII (18根)
   ├─ 1G    → 有 GTP 且引脚紧张选 SGMII (4根)
   │          无 GTP 或引脚够选 RGMII (12根) ← 90% 的情况
   │          仿真/学习且不愁引脚选 GMII (24根)
   ├─ 10G   → 大封装选 XGMII (74根，很少用)
   │          标准选法是用 USXGMII (4根差分 + GTY)
   └─ 多速率 → USXGMII
```

## 7. 接口复杂度 vs 引脚数 权衡图

```
引脚多 ▲
  74  │  XGMII ████████████████████
      │
  24  │  GMII  ██████
  18  │  MII   █████
  12  │  RGMII ███  ← 你在这里：引脚适中，DDR复杂
   8  │  RMII  ██
   4  │  SMII  █  SGMII █  USXGMII █
   0  ├──────────────────────────────────▶
      简单(SDR)    中等(DDR)    复杂(SerDes)  复杂度

省引脚 ←────────────────→ 复杂度增加
(好事)                  (代价)
```

> RGMII 的位置很巧妙：比 GMII 少一半引脚，但复杂度的增加（DDR）是 FPGA 硬核能消化的——IDDR/ODDR 原语足够成熟。这就是它成为主流的原因。

## 8. 采样方式详解：SDR / DDR / SerDes

### 8.1 SDR（Single Data Rate，单沿采样）

```
时钟周期的每个上升沿传一次数据。

clk     _/‾‾‾‾‾‾\___/‾‾‾‾‾‾\___/‾‾‾‾‾‾\_
DATA    ──< D0 >────< D1 >────< D2 >──
           ↑            ↑            ↑
        上升沿        上升沿        上升沿
        采 D0         采 D1         采 D2

每个时钟周期 = 1 次数据传输
```

| 特性 | 说明 |
|------|------|
| 每个时钟周期传几次 | **1 次**（只上升沿） |
| 数据带宽 | 位宽 × 时钟频率 |
| 例：GMII @125MHz | 8 bit × 125 MHz = **1 Gbps** |
| FPGA 实现 | 普通寄存器，`always @(posedge clk)` |
| 时序约束 | 只需要上升沿的 setup/hold |
| 优点 | 最简单，时序最宽松 |
| 缺点 | 同样带宽需要更大位宽或更高频率 → 更多引脚或更难布线 |
| 典型接口 | MII、RMII、SMII、GMII |

### 8.2 DDR（Double Data Rate，双沿采样）

```
时钟周期的上升沿和下降沿各传一次数据。

clk     _/‾‾‾‾‾‾\___/‾‾‾‾‾‾\___/‾‾‾‾‾‾\_
DATA    ──<D0>─<D1>──<D2>─<D3>──<D4>─
           ↑     ↑      ↑     ↑
        上升沿 下降沿  上升沿 下降沿
        采 D0  采 D1   采 D2  采 D3

每个时钟周期 = 2 次数据传输（带宽翻倍）
```

| 特性 | 说明 |
|------|------|
| 每个时钟周期传几次 | **2 次**（上升沿 + 下降沿） |
| 数据带宽 | 位宽 × 时钟频率 × 2 |
| 例：RGMII @125MHz | 4 bit × 125 MHz × 2 = **1 Gbps** |
| FPGA 实现 | **IDDR/ODDR 硬核原语**（不能用普通 always） |
| 时序约束 | 上升沿 + 下降沿都要约束（`-clock_fall -add_delay`） |
| 优点 | 同样时钟频率下带宽翻倍 → 位宽减半 → 省引脚 |
| 缺点 | 建立/保持时间窗口缩到 SDR 的一半，时序紧 |
| 典型接口 | **RGMII**、XGMII、DDR3/DDR4 SDRAM |

#### 为什么 DDR 比 SDR 复杂

```
SDR (GMII 8-bit):
  setup  ████████░░  数据必须在时钟沿前 ≥2ns 稳定
  hold       ░░████  数据必须在时钟沿后 ≥0ns 稳定
  窗口 ≈ 8ns (整个半周期都可用)

DDR (RGMII 4-bit):
  setup   ████░░░░  上升沿数据在上升沿前 ≥1ns 稳定
  hold        ░░██  上升沿数据在上升沿后 ≥1ns 稳定
  窗口 ≈ 4ns → 紧接着又要准备下降沿的数据
  
  时序裕量是 SDR 的一半，对 PCB 走线和 I/O 约束要求更高
```

#### RGMII DDR 代码实现

**发送（ODDR）：**

```verilog
// 上升沿输出低 4 位，下降沿输出高 4 位
ODDR #(.DDR_CLK_EDGE("OPPOSITE_EDGE"), .SRTYPE("ASYNC"))
  u_txd_oddr (
    .D1(gmii_txd[i]),      // 上升沿 → 低 nibble (bit [3:0])
    .D2(gmii_txd[i+4]),    // 下降沿 → 高 nibble (bit [7:4])
    .Q (rgmii_txd[i])      // DDR 输出
);
```

**接收（IDDR）：**

```verilog
// 上升沿抓到 Q1，下降沿抓到 Q2
IDDR #(.DDR_CLK_EDGE("SAME_EDGE_PIPELINED"), .SRTYPE("ASYNC"))
  u_rxd_iddr (
    .D (rgmii_rxd[i]),
    .Q1(rxd_q1[i]),        // 上升沿抓到的 → 高 nibble
    .Q2(rxd_q2[i]),        // 下降沿抓到的 → 低 nibble
    .C (rgmii_rxc)
);

// 拼接还原 8-bit
assign gmii_rxd = {rxd_q1, rxd_q2};
```

### 8.3 SerDes（Serializer/Deserializer，串行器/解串器）

```
低速并行数据 → 高速串行比特流 → 差分对传输 → 高速串行比特流 → 低速并行数据

┌──────┐    ┌─────────┐    差分对     ┌─────────┐    ┌──────┐
│ 8bit │───▶│ 串行器   │─── TX+/TX- ──▶│ 解串器   │───▶│ 8bit │
│ 125M │    │ 1.25GHz │    一根线      │ 1.25GHz │    │ 125M │
└──────┘    └─────────┘               └─────────┘    └──────┘

8 位并行数据 125MHz
  → 串化为 1 位数据 1.25GHz (8×125M 加上 8b/10b 编码开销)
  → 通过差分对传输
  → 解串还原为 8 位并行数据
```

| 特性 | 说明 |
|------|------|
| 物理介质 | **差分对**（两根线，相位相反），抗干扰极强 |
| 引脚数 | 最少——1 路只需 **2 根信号线** (TX+/TX-) + 有时外接参考时钟 |
| FPGA 实现 | **GTP/GTX/GTY 硬核收发器**（7 系列叫 GTP，UltraScale 叫 GTY） |
| 编码方式 | 8b/10b 或 64b/66b（时钟嵌入数据流中，无需单独时钟线） |
| 数据带宽 | 线速率 × 编码效率 |
| 例：SGMII @1.25Gbps | 1.25G × 8/10 = 1 Gbps 有效带宽 |
| 优点 | 引脚最少，抗干扰最强，PCB 布线最简单 |
| 缺点 | **调试极其困难**：需要 ≥2.5GHz 示波器 + 差分探头；GTP 配置参数多，一个参数不对就不通 |
| 典型接口 | SGMII、QSGMII、USXGMII、PCIe、SATA、USB 3.0 |

#### SerDes 为什么难调试

```
SDR (GMII):
  示波器探头 → 点在线路上 → 直接看到 0/1 电平
  普通 100MHz 示波器就能看

DDR (RGMII):
  示波器探头 → 点在线路上 → 看到 125MHz DDR 波形
  需要 ≥200MHz 示波器 + 眼图模板

SerDes (SGMII):
  1.25GHz 差分对 → 普通示波器根本看不见 → 眼图完全闭合
  → 只能靠协议分析仪或者反复盲调 GTP 参数
  → 或者依赖厂商提供的参考设计
```

### 8.4 三种采样方式对比总表

| | SDR | DDR | SerDes |
|---|:--:|:--:|:--:|
| 每次钟传几次数据 | 1 次 | **2 次** | N 次（串行） |
| 引脚数 | 多 | 中 | **极少（2根）** |
| FPGA 实现 | 普通 DFF | IDDR/ODDR 原语 | GTP/GTX 硬核 |
| 时序约束 | 上升沿 | 上升沿 + 下降沿 | 不约束（硬核内部处理） |
| 时钟 | 单独时钟线 | 单独时钟线 | **时钟嵌入数据** |
| 调试难度 | ☆ | ★★ | ★★★★★ |
| 抗干扰 | 一般 | 一般 | **极强**（差分） |
| PCB 走线 | 需等长 | 需严格等长 | 阻抗控制即可 |
| 典型频率 | 25~125 MHz | 125~200 MHz | 1.25~25+ GHz |
| 接口举例 | MII, GMII | **RGMII**, DDR 内存 | SGMII, PCIe |
| 适合谁 | 初学者 | 有点经验 | 有高速设计背景 |

### 8.5 一句话总结

```
SDR:   "一个节拍传一次，简单粗暴，费引脚"
DDR:   "一个节拍传两次，引脚减半，时序翻倍"
SerDes: "全串成一根线，引脚最少，调试最痛"
```
